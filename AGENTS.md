## Ownership

- Keep lifecycle hooks and compaction orchestration in `src/index.ts`; keep the in-memory request snapshot tracker, snapshot capture, matching, and reuse, and compaction's Pi-equivalent request context in `src/request-snapshot.ts`.
- Capture the canonical source independently of `context` hook input. Leave `context` messages unchanged so other extensions see Pi's own messages in any load order; project the checkpoint in `context_with_system`, after every `context` handler, and capture that projection. Require an unchanged canonical source, session, model, and backend through provider preparation and retries. Bind later reuse to that canonical prefix, not equality between source and projection. Capture the effective prompt through `ctx.getSystemPrompt()`. Match wire reuse against the effective prompt, thinking level, tool definitions/selection, and Pi settings except fields that affect only presentation in Pi; verify each excluded field against Pi sources. Accept a settled per-run override only while the current prompt equals that override or its unchanged source prompt. At `agent_settled`, accept the base prompt Pi then reports for the run's last request only while every other input is unchanged. Never copy response identifiers, prewarm operations, output limits, transport flags, or credentials from a previous payload.
- Preserve the complete observed wire prefix, including mid-history tool loading and provider history projections, when the snapshot matches; otherwise let Pi serialize transcript declarations. Capture wire input before checkpoint replay and replay it once per request. Reuse only independent fields when the observed input depends on server-side conversation references; reconstruct history locally. Mark both the join and the transcript end with private boundaries and remove them before sending. Treat items Pi serializes after the transcript end as request-level: replace the observed request's matching tail instead of keeping it in the prefix, and send Pi's own serialization when the tails differ in shape; preserve contextual-message flags when splicing and blocking images. Pi exposes no current visibility revision, so document that unobserved hide-only changes cannot invalidate the snapshot. Apply image blocking to replayed raw history as well as fresh context.
- Reject both context and wire reuse when a new canonical suffix message matches content present only in the observed projection; never guess whether to remove a repeated message. Compare this overlap through Pi's LLM conversion without timestamps, while keeping full fingerprints for canonical history validation. Discard capture when request checkpoint projection fails. Validate retained messages exactly against the canonical transcript; trace request-local edits back to them by role, timestamp, tool call ID, and custom type; skip replay when the request omits the summary or provenance is ambiguous.
- Keep checkpoint persistence, canonical and request-time Pi projection, and legacy fingerprint normalization in `src/checkpoint.ts`. Preserve checkpoint version 1, marker prefixes, completion entry identifiers, and exact recognition of persisted legacy summaries. New recovery prompts name the current package. Hash keys in UTF-16 code-unit order; normalize locale-sorted legacy fingerprints only after exact validation against the creation-time branch.
- Keep provider identity in `src/capability.ts`, Responses wire rules in `src/protocol.ts`, and provider adaptation and transport defaults in `src/remote.ts`. Dispatch through Pi's `ModelRegistry.streamSimple()` with SSE so each V2 request sends its feature header and checks its endpoint.
- Keep whole-attempt retry evidence and bounded waits in `src/remote-retry.ts`. Retry the complete SSE request and collection at most `min(configured retries, 2)` additional times; set provider retries to zero and allow one fetch call per attempt. Preserve the prepared body and backend while re-authenticating; leave redirect handling to the provider and fetch. Retry only on explicit transient evidence; permanent errors, invalid protocol output, cancellation, and session changes veto retries.
- Keep V2 eligibility in `src/capability.ts`: honor explicit `compat.remoteCompaction` metadata, otherwise match `gpt` in the model ID case-insensitively on `openai-responses` or `openai-codex-responses`, whose payloads carry `input` and whose request URLs pass endpoint validation. Do not gate eligibility on provider or the official base URL; preserve endpoint validation and backend identity binding.
- Bind checkpoint replay to the backend and exactly validated retained messages. Skip opaque replay on incompatibility or projection mismatch while allowing ordinary requests to continue. On the wire, require exactly one marker occurrence and replace only the marker, keeping content other hooks add around or join to it. Keep model selection passive, preserve ordinary payload routing, and use the selected chat model for V2; leave window handling to Pi and the provider.
- Bind compaction installation and retries to the current session; discard results only when the session changes or compaction is aborted. Never cancel or discard compaction because the selected model changed; finish with the model selected at start, as Pi does, and warn when the new checkpoint cannot replay on the current backend.
- Keep configured fallback model resolution and Pi native text summarization in `src/fallback.ts`. Keep the versioned configuration format, bounded reads, and revision-bound atomic updates in `src/fallback-settings.ts`; keep `/codex-compaction` interaction in `src/fallback-command.ts`. Read `extensions/pi-codex-compaction/config.json` under Pi's agent directory once at compaction start, default V2 to enabled, and validate fallback only when needed. Disabling V2 skips new remote compaction requests but preserves checkpoint replay. Resolve models and authentication through Pi, leave the chat model unchanged, and cancel compaction if an enabled fallback fails. Pass the selected model unchanged to native compaction; let the routed physical model and provider determine each summary's output limit.
- After transient V2 failure over a validated compatible checkpoint, preserve the opaque history and summarize only the newly dropped messages. Never send opaque items to the text summarizer. Replay the base, supplemental summary and retained tail exactly once for chat and subsequent V2. Keep native fallback when V2 is disabled or unsupported. Lock configuration updates across Pi processes while rereading the revision and atomically replacing the file.
- Keep history grouping and marked-text matching in `src/history-groups.ts`, message classification in `src/retention-input.ts`, selection and truncation in `src/retention.ts`, tool-output trimming and item estimates in `src/context-window.ts`, and UTF-8 estimates in `src/text-budget.ts`.
- Keep the fixed 64,000-token plaintext retention ceiling, image/label atomicity, newest-first selection, Unicode boundaries, and source immutability.
- Keep image decoding and byte estimates in `src/image-budget.ts`; estimate each remote request once and share its URL-keyed snapshot with trimming and retention.
- Follow enabled defaults from Codex `rust-v0.172.0`; check hook XML edge cases against its actual quick-xml parser.

## Engineering & Acceptance Standards

- **Root cause & single owner**: Fix defects at their architectural owner rather than layering patches. Treat 2+ `fix(...)` commits in the same area as a misplaced owner and restructure the owner instead of adding another patch. Give every shared rule, constant, type, default, and error class one owner and derive all other views from it.
- **Parse at boundaries, trust inside**: Validate, narrow types, apply defaults, and reject invalid states at the outermost boundary that owns them. Pass narrowed types downstream and omit redundant internal null checks, fallbacks, or guards for states already excluded by boundaries or types.
- **Flat control flow & restrained abstraction**: Reduce branching structurally with guard clauses, table-driven dispatch, discriminated unions with exhaustive `switch`, and decision/execution separation. Reject fake refactors that move the same branches into mechanical helpers, replace boolean flags with strategy-function parameters, or add wrapper layers, factories, or inheritance just to hide an `if`. Every abstraction must address current pain and reduce net branches, concepts, or lines.
- **Fail fast & uniform error shapes**: In `catch`, either reclassify with context while preserving `cause` or rethrow. Never return silent defaults (`undefined`, `""`, `0`, `[]`) to mask failure; document any intentional ignore in an adjacent comment. Use consistent, named error classes per failure category (cancellation, validation, protocol, configured summary failure) and state the field, violated rule, and allowed forms in validation errors.
- **Explicit ownership & lifecycle**: Keep creator-releases and owner-mutates discipline for sessions, streams, locks, and snapshots; avoid implicit globals and scattered shared mutable state.
- **Framework reuse with source proof**: Reuse native Pi (`@earendil-works/pi-*`) capabilities directly instead of reimplementing them unless a verified limitation prevents it. Cite `path:line` from installed `node_modules/` for any claim about what Pi provides or lacks.
- **Zero internal baggage, strict external contracts**: Delete obsolete internal branches and compatibility shims while keeping external contracts intact (Pi entrypoint and hooks, `/codex-compaction` UX, `config.json` v1/v2, persisted checkpoint v1/v2, legacy summary recognition, and peer dependency ranges).
- **Deterministic English output & cache stability**: Keep all user-facing and model-facing messages, prompts, and errors in English and deterministic (identical inputs produce identical wire bytes independent of timing or iteration order). Preserve stable request prefixes for prompt caching across turns and replays.
- **Hot-path discipline & measured claims**: Avoid unnecessary copies, intermediate arrays, or extra passes on streaming, serialization, and retention paths. Support any performance or memory claim with a repeatable benchmark script running at least 5 alternating baseline/candidate pairs on real inputs.
- **Prove production reachability** before reporting or fixing a defect. Name the supported entry point and show how its callers, guards, and lifecycle permit the triggering input, state, and timing. Treat a failure reachable only by a test's direct low-level call or state mutation that bypasses those constraints as a test setup artifact. It provides no basis for a defect report, production guard, or regression test. A documented public API can serve as the entry point for calls within its own contract.
- **Clean code & real-path acceptance**: Keep comments limited to non-obvious intent, external constraints, or trade-offs; remove dead branches, unused exports/parameters/variants, commented-out code, and TODOs. Test production paths and observable behavior without adding test-only hooks, parameters, or exports to `src/`, and include a regression test that fails before the fix. Never accept changes on green tests alone; read the full changed production files for structure, risk, real defects, and contract drift.
