## Ownership

- Keep lifecycle hooks and compaction orchestration in `src/index.ts`; keep the in-memory request snapshot tracker, snapshot capture, matching, and reuse, and compaction's Pi-equivalent request context in `src/request-snapshot.ts`.
- Capture ordinary context through `context_with_system` and the effective prompt through `ctx.getSystemPrompt()` before ordinary provider requests. Bind context reuse to the session, model, backend, and unchanged canonical source prefix. Match wire reuse against the effective prompt, thinking level, tool definitions/selection, and Pi settings; accept a settled per-run override only while the current prompt equals that override or its unchanged source prompt. Never copy response identifiers, prewarm operations, output limits, transport flags, or credentials from a previous payload.
- Preserve the complete observed wire prefix, including mid-history tool loading and provider history projections, when the snapshot matches; otherwise let Pi serialize transcript declarations. Capture wire input before checkpoint replay and replay it once per request. Reuse only independent fields when the observed input depends on server-side conversation references; reconstruct history locally. Remove the private serialization boundary before sending; preserve contextual-message flags when splicing and blocking images. Pi exposes no current visibility revision, so document that unobserved hide-only changes cannot invalidate the snapshot. Apply image blocking to replayed raw history as well as fresh context.
- Keep checkpoint persistence, canonical Pi projection, and legacy fingerprint normalization in `src/checkpoint.ts`. Preserve checkpoint version 1, marker prefixes, completion entry identifiers, and exact recognition of persisted legacy summaries. New recovery prompts name the current package. Hash keys in UTF-16 code-unit order; normalize locale-sorted legacy fingerprints only after exact validation against the creation-time branch.
- Keep provider identity in `src/capability.ts`, Responses wire rules in `src/protocol.ts`, and provider adaptation and transport defaults in `src/remote.ts`. Dispatch through Pi's `ModelRegistry.streamSimple()` with SSE so each V2 request sends its feature header and checks its endpoint.
- Keep whole-attempt retry evidence and bounded waits in `src/remote-retry.ts`. Retry the complete SSE request and collection at most `min(configured retries, 2)` additional times; set provider retries to zero and allow one fetch call per attempt. Preserve the prepared body and backend while re-authenticating; leave redirect handling to the provider and fetch. Retry only on explicit transient evidence; permanent errors, invalid protocol output, cancellation, and ownership changes veto retries.
- Keep V2 eligibility in `src/capability.ts`: honor explicit `compat.remoteCompaction` metadata, otherwise match `gpt` in the model ID case-insensitively on `openai-responses` or `openai-codex-responses`, whose payloads carry `input` and whose request URLs pass endpoint validation. Do not gate eligibility on provider or the official base URL; preserve endpoint validation and backend identity binding.
- Bind checkpoint replay to the backend and exact retained-message projection. Skip opaque replay on incompatibility or projection mismatch while allowing ordinary requests to continue. Keep model selection passive, preserve ordinary payload routing, and use the selected chat model for V2; leave window handling to Pi and the provider.
- Bind compaction installation and retries to the current session and selected model; discard results when ownership changes.
- Keep configured fallback model resolution and Pi native text summarization in `src/fallback.ts`. Keep the versioned configuration format, bounded reads, and revision-bound atomic updates in `src/fallback-settings.ts`; keep `/codex-compaction` interaction in `src/fallback-command.ts`. Read `extensions/pi-codex-compaction/config.json` under Pi's agent directory once at compaction start, default V2 to enabled, and validate fallback only when needed. Disabling V2 skips new remote compaction requests but preserves checkpoint replay. Resolve models and authentication through Pi, leave the chat model unchanged, and cancel compaction if an enabled fallback fails. Ignore virtual display limits when sizing native summaries; let registry routing cap each request to the physical model.
- Allow native fallback with an active opaque checkpoint; document that text summaries cannot include encrypted history. Lock configuration updates across Pi processes while rereading the revision and atomically replacing the file.
- Keep history grouping and marked-text matching in `src/history-groups.ts`, message classification in `src/retention-input.ts`, selection and truncation in `src/retention.ts`, tool-output trimming and item estimates in `src/context-window.ts`, and UTF-8 estimates in `src/text-budget.ts`.
- Keep the fixed 64,000-token plaintext retention ceiling, image/label atomicity, newest-first selection, Unicode boundaries, and source immutability.
- Keep image decoding and byte estimates in `src/image-budget.ts`; estimate each remote request once and share its URL-keyed snapshot with trimming and retention.
- Follow enabled defaults from Codex `rust-v0.159.2`; check hook XML edge cases against its actual quick-xml parser.
- Load this extension before context handlers that rewrite retained messages; preserve exact checkpoint fingerprint checks.
