## Ownership

- Keep lifecycle hooks and compaction orchestration in `src/index.ts`; keep the in-memory request snapshot tracker, snapshot capture, matching, and reuse, and compaction's Pi-equivalent request context in `src/request-snapshot.ts`.
- Capture ordinary context through `context_with_system` and the effective prompt through `ctx.getSystemPrompt()` before ordinary provider requests. Bind context reuse to the session, model, backend, and unchanged canonical source prefix. Bind provider-ready non-tool field reuse to unchanged prompt, thinking level, tool definitions/selection, and Pi settings as well; never copy response identifiers, output limits, transport flags, or credentials from a previous payload.
- Pi hides tool declarations after context hooks and exposes no current visibility revision. Preserve internal tool metadata for Pi's historical-call serialization, then omit all V2 wire schemas after snapshot reuse and checkpoint replay. Do not reuse last-observed visibility as current authorization. Apply image blocking to replayed raw history as well as fresh context.
- Keep checkpoint persistence, canonical Pi projection, and legacy fingerprint normalization in `src/checkpoint.ts`. Preserve checkpoint version 1, marker prefixes, completion entry identifiers, and exact recognition of persisted legacy summaries. New recovery prompts name the current package. Hash keys in UTF-16 code-unit order; normalize locale-sorted legacy fingerprints only after exact validation against the creation-time branch.
- Persist optional producing-model window and compatibility metadata without requiring it on v1 checkpoints; ignore malformed optional values before cloning. Read `compactionModelHash` only from explicit `compat.remoteCompaction` metadata with `protocol: "v2"`. Never derive a hash from identity, URLs, window sizes, or opaque content, or backfill a legacy checkpoint's creation-time hash from the current catalogue.
- Keep provider identity in `src/capability.ts`, Responses wire rules in `src/protocol.ts`, and provider adaptation and transport defaults in `src/remote.ts`. Dispatch through Pi's `ModelRegistry.streamSimple()` with SSE so each V2 request sends its feature header and checks its endpoint.
- Keep whole-attempt retry evidence and bounded waits in `src/remote-retry.ts`. Retry the complete SSE request and collection at most `min(configured retries, 2)` additional times; set provider retries to zero and allow one fetch per attempt. Preserve the prepared body, backend, and actual prepared-model window/hash while re-authenticating; reject automatic redirects. Persist metadata returned from the actual prepared model, not the selected-model approximation. Retry only on explicit transient evidence; permanent errors, invalid protocol output, cancellation, and ownership changes veto retries.
- Keep V2 eligibility in `src/capability.ts`: honor explicit `compat.remoteCompaction` metadata, otherwise match `gpt` in the model ID case-insensitively on `openai-responses` or `openai-codex-responses`, whose payloads carry `input` and whose request URLs pass endpoint validation. Do not gate eligibility on provider or the official base URL; preserve endpoint validation and backend identity binding.
- Keep pure compatibility assessment in `src/model-transition.ts`. Compare known hashes before model IDs, and never let matching hashes override backend boundaries. Same-backend model changes without comparable hashes remain unknown and warn; they are not verified-compatible. Reject known mismatches, invalid projection, or a different serialized request model by calling public `ctx.abort()` before throwing, because Pi catches hook exceptions.
- Prepare smaller models only through public Pi APIs. `model_select` runs after selection; request preparatory compaction through its callbacks only while idle, never from a live provider hook. A larger previous/producing model must share the backend without known hash conflicts. Preserve its actual identity and metadata on the new checkpoint, keep the selected chat model unchanged, and keep old history on preparation failure. Bind async work and retries to the session and selected model, including explicit endpoint and compatibility metadata.
- Keep full-payload estimates in `src/model-budget.ts`: count plaintext/unknown JSON and semantic opaque/image estimates, without decrypting content. Use the floored 95% physical window minus the larger of model maximum output and Pi compaction reserve; invalid budgets fail closed. During smaller-model preparation reserve another `min(4096, ceil(5% of contextWindow))` for the next turn. Recheck the complete retained result before installation and expanded ordinary input at this extension's provider hook; these heuristics do not prove tokenizer or later-hook equivalence.
- Keep configured fallback model resolution and Pi native text summarization in `src/fallback.ts`. Keep the versioned configuration format, bounded reads, and revision-bound atomic updates in `src/fallback-settings.ts`; keep `/codex-compaction` interaction in `src/fallback-command.ts`. Read `extensions/pi-codex-compaction/config.json` under Pi's agent directory once at compaction start, default V2 to enabled, and validate fallback only when needed. Disabling V2 skips new remote compaction requests but preserves checkpoint replay. Resolve models and authentication through Pi, leave the chat model unchanged, and cancel compaction if an enabled fallback fails. Ignore virtual display limits when sizing native summaries; let registry routing cap each request to the physical model.
- Cancel native fallback while an opaque checkpoint is active: Pi's native preparation cannot preserve that history. Lock configuration updates across Pi processes while rereading the revision and atomically replacing the file.
- Keep history grouping and marked-text matching in `src/history-groups.ts`, message classification in `src/retention-input.ts`, selection and truncation in `src/retention.ts`, tool-output trimming and item estimates in `src/context-window.ts`, and UTF-8 estimates in `src/text-budget.ts`.
- Preserve the default 64,000-token plaintext retention ceiling. Only smaller-model preparation supplies a lower optional budget; zero means opaque-only history, invalid bounds throw, and image/label atomicity, newest-first selection, Unicode boundaries, and source immutability remain intact.
- Keep image decoding and byte estimates in `src/image-budget.ts`; estimate each remote request once and share its URL-keyed snapshot with trimming and retention.
- Follow enabled defaults from Codex `rust-v0.159.2`; check hook XML edge cases against its actual quick-xml parser.
- Load this extension before context handlers that rewrite retained messages; preserve exact checkpoint fingerprint checks.
