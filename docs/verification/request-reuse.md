# 实际请求复用与会话集成测试验证记录

> 本文主体保留 2026-10-02 对指定历史提交的验证记录。当前边界先列于下文；历史部分中的“工具声明与完整前缀复用”、测试总数和耗时只描述当时的实现。完整源码对照见 [Codex V2 源码对照](codex-v2-parity.md)。

## 当前边界

V2 保留结构化工具声明和历史工具加载记录；符合会话、模型、后端、历史前缀及当前设置约束时，复用普通请求的声明前缀和系统指令、思考、缓存、服务等级等字段。没有可用快照时由 Pi 序列化会话声明。Pi 未公开隐藏工具投影的修订号，因此只改变隐藏状态而公开输入不变时，旧快照仍可能被复用。离线测试验证请求内容，不保证服务端缓存命中。

V2 对完整 SSE 请求与收集过程重试：额外次数不超过 Pi provider 设置与 2 的较小值，内层 HTTP 重试为 0。首次准备完成后固定请求体与后端，后续尝试重新认证并校验归属；只有明确暂时故障才重试，无效/重复压缩输出、永久错误和取消不会重试。重定向沿用 provider 和 fetch，传输固定为 SSE，未实现 Codex 的 WebSocket 到 HTTP 切换。

检查点重放绑定后端和保留消息指纹。同后端模型切换继续重放；后端不匹配或消息投影失败时跳过加密历史，普通请求继续使用可读取的上下文。扩展不额外限制普通 payload 的模型路由，模型选择也不会触发准备压缩。后续 V2 使用当前对话模型，窗口处理由 Pi 和 provider 决定。

已有 V2 检查点也允许原生文字摘要回退。文字摘要无法解读加密历史，成功后它成为活动上下文；原持久化检查点保持不变。配置保存使用跨进程锁，检查点图片重放遵守当前图片读取设置。

这些检查仍受本扩展的钩子位置限制：之后执行的扩展可以继续改写请求，Pi 的隐藏状态和服务端缓存状态也不由快照证明。离线 fixture 不用于推断摘要质量、线上模型兼容性或费用。当前回归范围与运行命令见[对照记录](codex-v2-parity.md#9-本轮验证与复现边界)；下方 Windows/TS7 耗时记录保留原样。

## 测试范围

新增的 [会话集成测试](../../tests/session-integration.test.ts) 通过 Pi 的 `createAgentSession()`、扩展加载器、会话文件和真实 provider 序列化器运行。覆盖 `openai-responses` 与 `openai-codex-responses`：普通对话、首次 V2 压缩、压缩后继续对话、关闭并重新打开会话、再次压缩，以及继续使用第二次压缩结果。

这些新增会话请求统一使用 `gpt-6.1-sol`。测试在网络边界注入模拟 SSE 响应，不调用线上模型，不使用真实凭据。记录的耗时反映本地验证成本，不能据此推断模型延迟、摘要质量、缓存命中率或费用变化。

请求复用测试让另一个扩展修改普通请求的指令、思考参数、缓存键、缓存保留时间、服务等级和文本详细程度，并通过 Pi 的工具声明隐藏机制隐藏一个内部工具。压缩请求必须保留这些已观察到的字段，以及普通请求的完整历史前缀。上一次请求的 `previous_response_id` 和输出上限不会被照搬。

会话、模型、服务地址、历史前缀、系统提示词、工具定义、思考等级或设置改变时，单元测试检查旧快照失效。集成测试另外检查思考等级和启用工具变化后的实际请求。快照只能观察本扩展的 `before_provider_request` 钩子执行时已经形成的请求，无法捕获之后运行的扩展对请求的修改。

恢复兼容测试使用保存过的旧版摘要作为输入，重新打开真实 Pi 会话并检查压缩历史仍会发送给 provider。新提示引用当前包 `@criogaid/pi-codex-compaction`；旧版摘要的精确识别继续保留，不改写用户已有会话。

文案清理删除了 3 个只固定菜单名称和说明文字的测试。其余相关断言改为检查配置写入、错误分类、菜单交互、图片占位合并、截断后保留内容和省略数量。协议字段、历史摘要输入兼容、敏感信息保护仍有测试。测试总数从基线的 352 项变为 360 项：新增 11 项，删除 3 项。

## 复跑

在目标提交安装依赖后执行：

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
npm run pack:check
```

重复后三条命令三次可复跑完整验证。`npm test` 编译后，也可单独执行会话集成测试：

```sh
node --test dist/tests/session-integration.test.js
```
