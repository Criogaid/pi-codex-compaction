## 当前边界

V2 保留结构化工具声明和历史工具加载记录；符合会话、模型、后端、历史前缀及当前设置约束时，复用普通请求的完整 wire 前缀，以及系统指令、思考、并行工具调用、输出格式、verbosity、缓存模式/TTL、缓存键和服务等级。临时提示词结束后仅恢复到同一源提示词不会使快照失效；本轮结束时 Pi 改报基础提示词，若该轮最后一次请求的其他输入均未变化，也继续接受快照。主题、思考块显示、终端、编辑器和全屏显示等 Pi 0.99.1 与 1.0.4 中只影响显示或交互的设置不参与匹配，真正的提示词或其他设置变化仍会失效。没有可用快照时由 Pi 序列化会话声明。Pi 未公开隐藏工具投影的修订号，因此只改变隐藏状态而公开输入不变时，旧快照仍可能被复用。

快照记录 checkpoint 重放前的 input 和逐项上下文来源。压缩时由 Pi 序列化新增尾部，通过仅用于本地定位的边界项拼接完整旧前缀；该项在发送前移除。检查点在普通请求和 V2 中各重放一次，隐藏扩展消息仍不进入明文保留区。预热操作和诊断响应 ID 不随缓存策略复用。普通请求依赖 `previous_response_id`、`conversation` 或 `item_reference` 时，仅复用独立参数，历史由 Pi 从本地完整上下文重建。

源历史从会话管理器独立读取，不使用 `context` 钩子已经变换过的消息作为源版本。捕获投影、准备 provider 请求及重试时均验证源历史与会话、模型、后端未变；压缩时验证源历史仍是当前历史的完整前缀。新尾部若与投影独有内容重合，放弃上下文和 wire 快照并重建，不猜测哪条消息应被去重。原检查点投影失败时也不捕获该请求，保留消息的精确校验保持不变。

两种 Responses API 的回归测试覆盖本轮临时提示词结束后的字段复用、历史文本投影和显式缓存断点、中途隐藏的 additional_tools/工具搜索声明、重开会话后的再次压缩，以及整次重试的请求体一致性。完整前缀修复前，定向测试 22 项中 6 项失败。主题切换的两项回归在修复前均失败，修复后仅改主题再直接压缩，工具声明和已有 input 前缀仍与普通请求一致。当前在 Pi 1.0.4 上运行完整测试 635 项，634 项通过，1 项因 Windows 符号链接权限跳过。离线测试验证请求内容，不保证服务端缓存命中。

V2 对完整 SSE 请求与收集过程重试：额外次数不超过 Pi provider 设置与 2 的较小值，内层 HTTP 重试为 0。首次准备完成后固定请求体与后端，后续尝试重新认证并校验会话归属；压缩期间切换模型不取消请求，也不丢弃结果；只有明确暂时故障才重试，无效/重复压缩输出、永久错误和取消不会重试。重定向沿用 provider 和 fetch，传输固定为 SSE，未实现 Codex 的 WebSocket 到 HTTP 切换。

检查点重放绑定后端和保留消息指纹。同后端模型切换继续重放；后端不匹配或消息投影失败时跳过加密历史，普通请求继续使用可读取的上下文。扩展不额外限制普通 payload 的模型路由，模型选择也不会触发准备压缩。后续 V2 使用当前对话模型，窗口处理由 Pi 和 provider 决定。

已有 V2 检查点也允许原生文字摘要回退。文字摘要无法解读加密历史，成功后它成为活动上下文；原持久化检查点保持不变。配置保存使用跨进程锁，检查点图片重放遵守当前图片读取设置。

这些检查仍受本扩展的钩子位置限制：之后执行的扩展可以继续改写请求，Pi 的隐藏状态和服务端缓存状态也不由快照证明。离线 fixture 不用于推断摘要质量、线上模型兼容性或费用。当前回归范围与运行命令见[对照记录](codex-v2-parity.md#9-本轮验证与复现边界)；下方 Windows/TS7 耗时记录保留原样。

## 压缩期间切换模型的验证

压缩按开始时捕获的模型、请求体与后端完成，途中选择其他模型不再取消或丢弃结果。Pi 1.0.4 的 `AgentSession.compact()` 同样在开始时读取模型，安装前检查取消信号而不比较当前模型。会话变化和取消信号仍会终止本插件的压缩；重试认证解析出的后端漂移也仍被拒绝。

两种 Responses API 分别覆盖准备请求、发送请求、第二次重试准备和收到完成响应四个阶段，再区分同后端与不同后端，共 16 项真实会话测试。每项与未切换的独立运行比较请求次数、地址和完整请求体，仅归一化 fixture 工作目录；缓存键由相同的请求扩展固定。检查点始终绑定开始时模型，用户选择的新模型保持不变，普通请求前缀和 prompt_cache_* 字段继续复用。

另有 4 项测试验证安装后的后端提示：同后端和未切换不提示，不同后端与无模型提示，同一检查点不重复提示，不同检查点独立计数。12 项取消测试覆盖认证、准备前后、发送、响应和重试阶段的会话变化与 abort；已有晚到响应和文字回退会话变化测试继续通过。新增两项配置文字回退测试确认换模型后仍使用配置的摘要模型完成，一项确认中途 abort 丢弃摘要。

环境：Windows `10.0.26100` x64，Intel Core i9-12900KS，24 个逻辑处理器；Node `v26.10.0`，npm `11.19.1`，Pi `0.99.1`，TypeScript `7.0.2`。两组测量使用相同已安装依赖，没有重新安装依赖或主动清理系统缓存。

每轮依次启动 `npm run typecheck`、`npm test`、`npm run pack:check`，通过 `performance.now()` 记录每个子进程从启动到结束的墙钟耗时，四舍五入到毫秒。`npm test` 和 `pack:check` 均包含 TypeScript 编译。下表的合计是三个命令耗时之和。

| 版本 | 轮次 | typecheck | npm test | pack:check | 合计 | 结果 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 修改前 `6016078` | 1 | 423 ms | 5936 ms | 2273 ms | 8632 ms | 全部通过，352 项测试 |
| 修改前 `6016078` | 2 | 496 ms | 6391 ms | 2503 ms | 9390 ms | 全部通过，352 项测试 |
| 修改前 `6016078` | 3 | 467 ms | 6224 ms | 2315 ms | 9006 ms | 全部通过，352 项测试 |
| 修改后 `bc5ed5d` | 1 | 452 ms | 6308 ms | 2313 ms | 9073 ms | 全部通过，360 项测试 |
| 修改后 `bc5ed5d` | 2 | 475 ms | 6173 ms | 2315 ms | 8963 ms | 全部通过，360 项测试 |
| 修改后 `bc5ed5d` | 3 | 466 ms | 6308 ms | 2271 ms | 9045 ms | 全部通过，360 项测试 |

每次 `pack:check` 的 2 项检查均通过，确认 npm 包包含运行模块、排除测试及构建产物，并能由 Pi 加载声明的源码入口。上述六轮没有失败、取消或跳过的测试；最终 `git diff --check` 也通过。

整轮合计的中位数从 9006 ms 变为 9045 ms，增加 39 ms，约 0.43%。`npm test` 的中位数从 6224 ms 变为 6308 ms。样本只有三轮，且测试内容有增减，这些数字仅作为此次验证记录。

## 复跑

在目标提交安装依赖后执行：

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
npm run pack:check
```

重复后三条命令三次可复跑完整验证。`npm test` 编译后，也可单独执行会话集成测试：

```sh
node --test dist/tests/session-integration.test.js
```

本地原始计时记录保存在被 Git 忽略的 `dist/request-reuse-baseline.json`、`dist/request-reuse-after.json` 及相应每轮日志中；本文件保存可随仓库查阅的环境、版本、方法和全部测量结果。
